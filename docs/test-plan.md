# Test plan

## Scope

In scope: join behaviour of real hostapd/wpa_supplicant builds over emulated radios
(`mac80211_hwsim`) across security modes, PMF, band and channel; DHCP/DNS on the lab network;
VLAN segmentation; Android client state handling on the emulator.

Out of scope: RF behaviour (interference, multipath, attenuation, signal level), vendor chipset
and driver differences, consumer router firmware and mesh, BLE/Zigbee/Thread/Matter,
throughput and performance.

## Environment

| Item | Value |
|---|---|
| Host OS | Ubuntu 24.04 VM, 4 GB RAM, 25 GB disk |
| Radios | `mac80211_hwsim radios=4`: `ap0` (root ns), `sta1..3` (`ns-client1..3`) |
| Capture | `hwsim0` (sees every emulated frame) |
| Lab network | 192.168.50.0/24, gateway + DHCP + DNS on `ap0` (dnsmasq) |
| Regulatory domain | US (`iw reg set US`), 5 GHz channels 36-48 |
| Versions | Recorded in `lab/inventory.yaml` (`lab/setup_lab.sh --versions`) |

## Entry criteria

1. Setup checkpoint passed by hand: WPA2 AP on `ap0`, `sta1` joins, gets a lease, resolves a name.
2. `sudo bash lab/setup_lab.sh` rebuilds the lab cleanly from a fresh boot.
3. Unit tests pass (`pytest tests/unit`).
4. Every AP in `lab/inventory.yaml` passes `pytest -m qualify` (6-step baseline:
   beacons, WPA3 join, WPA2 join, DHCP lease, DNS, reconnect).

## Exit criteria

1. Every Module 1 case has a pass rate of 100% (expected pass) or 0% (expected fail); any rate in
   between is logged as a flakiness issue.
2. Every non-compliant AP config is flagged by the harness.
3. Every Module 2 induced failure is classified at the documented stage, and the stage is
   confirmed in `docs/failure-signatures.md` against a real capture.
4. Module 3 isolation tests pass with the committed `lab/nftables/vlan-policy.nft`.
5. Each open bug has an issue with repro, config, pcap and logs; each fixed bug has a regression test.

## Module 1: connectivity matrix

Dimensions: security {Open, WPA2-PSK, WPA3-SAE, WPA2/WPA3 transition} x PMF {0,1,2} (Open: 0 only)
x channel {1, 6, 11, 36, 44} x client {wpa2-only, wpa3-capable} = **100 cases**, each joined
**5 times** (`--repeats`).

Client profiles:

| Profile | `key_mgmt` | `ieee80211w` | Models |
|---|---|---|---|
| wpa2-only | `WPA-PSK` | 0 | legacy client without PMF |
| wpa3-capable | `WPA-PSK SAE` | 1 | current client, PMF capable |

Per join the harness records: pass/fail and failing stage, auth+assoc+4-way time (ms, from
wpa_supplicant timestamps), DHCP time (ms), DNS resolution of `gw.lab` against dnsmasq, ping to
the gateway, and attaches the hostapd log, wpa_supplicant log and pcap.

### Compliance rules (WPA3-Personal)

* WPA3-Personal Only (SAE): PMF **required** (`ieee80211w=2`).
* WPA3-Personal Transition (WPA-PSK + SAE): PMF **capable, not required** (`ieee80211w=1`).

Non-compliant configs are still started and joined; the result is recorded but not asserted, and
the case is marked NON-COMPLIANT in the report.

### Expected results

Channel does not change the expectation, so one row per security/PMF pair.
Generated by `python -m testbed.matrix --markdown`.

| AP config | wpa2-only | wpa3-capable | Notes |
|---|---|---|---|
| Open / PMF disabled | PASS | PASS |  |
| WPA2-PSK / PMF disabled | PASS | PASS |  |
| WPA2-PSK / PMF optional | PASS | PASS |  |
| WPA2-PSK / PMF required | FAIL (association) | PASS | AP requires PMF; client does not support it |
| WPA3-SAE / PMF disabled | NON-COMPLIANT | NON-COMPLIANT | SAE-only requires PMF required |
| WPA3-SAE / PMF optional | NON-COMPLIANT | NON-COMPLIANT | SAE-only requires PMF required |
| WPA3-SAE / PMF required | FAIL (association) | PASS | WPA2-only client has no AKM in common with a WPA3-only AP |
| WPA2/WPA3 / PMF disabled | NON-COMPLIANT | NON-COMPLIANT | Transition requires PMF optional |
| WPA2/WPA3 / PMF optional | PASS | PASS |  |
| WPA2/WPA3 / PMF required | NON-COMPLIANT | NON-COMPLIANT | Transition requires PMF optional |

A case that passes when it is expected to fail is a bug.

## Module 3: VLAN isolation

| SSID | VLAN | Subnet | Allowed to reach |
|---|---|---|---|
| lab-mgmt | 10 | 10.10.10.0/24 | everything |
| lab-test | 20 | 10.10.20.0/24 | own subnet, DNS |
| lab-iot | 30 | 10.10.30.0/24 | own subnet, DNS |

Cases: correct-subnet lease per SSID; DNS from every SSID; IoT -> mgmt ping/TCP blocked;
mgmt -> IoT allowed; test -> IoT blocked; IoT <-> IoT allowed; IoT <-> IoT blocked with
`ap_isolate=1`.

## Module 4: Android (emulator, host only)

| Case | Threshold |
|---|---|
| Reconnect after Wi-Fi toggle | connected + ping within **30 s** |
| Airplane mode round trip | Wi-Fi returns to prior state within **15 s** |
| State reporting | SSID present, RSSI in [-100, 0] dBm, link speed > 0 |
| Degraded network (`delay gprs`, `speed edge`) | ping succeeds within **20 s** |

On failure the logcat excerpt (Wi-Fi and connectivity tags) and the ADB transcript are attached.
